|---|---|---|---|---|---|
| 1 | 2026-04-29 | Distribution | Publish as local-script open-source tool. | Tool needs local macOS access. | Hosted service. |
| 2 | 2026-04-29 | Cleanup safety | Default to preview/explicit actions for destructive cleanup. | Prevent data loss. | Fully automatic deletion. |
| 3 | 2026-04-29 | Scanner sizing | Use allocated disk usage. | Sparse VM/container files otherwise over-report. | Apparent file size only. |
| 4 | 2026-04-29 | AI provider | Keep OpenAI legacy for now; Gemini migration follow-up. | Avoid mixing provider migration into release hygiene. | Silent dual-provider fallback. |
| 5 | 2026-04-29 | Background AI | Use optional Gemini structured recommendations with local validation; no AI tool execution. | AI should help decide what to optimize without bypassing safety gates. | Letting the model directly call kill/delete tools. |
| 6 | 2026-04-29 | Chrome tabs | Close Chrome tabs only after fresh snapshot validation and explicit confirmation. | Tab indices can shift and tabs may contain unsaved work. | Autonomous bulk tab closing. |
| 7 | 2026-04-29 | AI auto optimization | `--ai` may automatically run safe RAM purge only; Gemini must never directly close apps, close tabs, kill processes, or delete files. | Owner wants automatic RAM optimization without breaking VS Code/agent jobs or destructive local state. | Fully autonomous model-driven cleanup. |
| 8 | 2026-04-29 | Dashboard widgets | Hiding AI or Chrome widgets also disables their dashboard polling timers. | Hidden panels should not keep inspecting tabs or spending AI calls. | Treating widget settings as visual-only. |
| 9 | 2026-04-29 | Server structure | Keep `server.py` as an 8-line executable shim and put dashboard state, routing, runtime, services, and assets under `mac_cleaner_server/`. | Prevent another 2k-line server monolith while preserving `./start` and `mac-cleaner`. | Replacing `http.server` or leaving dashboard code embedded in Python. |
| 10 | 2026-04-30 | Pub cache safety | Treat `~/.pub-cache` as protected report-only storage and refuse cleanup even from stale scan metadata. | It is a shared Dart/Flutter package store and deletion can break active builds, hot restart, and globally activated tools. | Leaving it review-cleanable because packages can be redownloaded. |
| 11 | 2026-08-10 | Product architecture | Replace the Python/server product with Tauri 2, a bundled local UI, shared Rust crates, and a Rust CLI; ship no localhost listener. | One native process can own lifecycle and monitoring while the frontend receives no ambient filesystem or process authority. | Porting the Python HTTP server or building a second privileged daemon. |
| 12 | 2026-08-10 | Cleanup authorization | Start with an empty automatic catalog; accept only backend candidate IDs, short-lived plans, native/typed confirmation, identity revalidation, and same-volume quarantine. | Language choice alone does not prevent broad or stale-path deletion. | Porting generic `Clean All`, sweeping `~/Library/Caches`, or client-supplied paths. |
| 13 | 2026-08-10 | Reclamation and recovery | Treat quarantine, restore, and permanent purge as separate journaled actions; purge exactly one revalidated entry per confirmation. | A quarantine move is recoverable but does not free disk, while bulk purge makes recovery failures harder to contain. | Claiming reclaimed bytes at quarantine time or permanently deleting during initial cleanup. |
| 14 | 2026-08-10 | Startup safety | Do not let a debug executable register for login; enable startup only from an installed `.app` after native confirmation. | A development-path LaunchAgent becomes stale and causes the startup failures reported by the owner. | Automatically enabling login on first launch. |
| 15 | 2026-08-10 | Storage diagnosis | Keep hotspot analysis read-only and distinct from cleanup authorization; classify exact paths as reviewable, tool-managed, or protected and show recovery cost. | Large size alone does not mean data is disposable, especially for Docker, simulators, SDKs, repositories, and application state. | Turning a disk-usage ranking into a Clean All list. |
| 16 | 2026-08-11 | Automatic memory recovery | Supersede legacy decision 7: monitor conservative availability, compression, swap, and derived pressure every 30 seconds; notify on sustained warning/critical pressure and offer user-confirmed Activity Monitor guidance. Never invoke `purge`, generate pressure, or automatically terminate apps. | The legacy `purge` command flushes disk buffers rather than application memory, while `memory_pressure -l critical` deliberately consumes memory. macOS already reclaims cached and compressed RAM. | Periodic disk-cache flushing, artificial memory pressure, privileged helpers, or autonomous app termination. |
